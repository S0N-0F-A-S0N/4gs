## 2024-11-11 - [O(n) Network Call Reduction]
**Learning:** Found an N+1 API call bottleneck in the `judge-service`. The duel iteration loops over challengers and fetched `leader_gens` (the current leader's generated images) on *every* loop iteration using `get_miner_generations` (which makes a network call to GitHub to read a JSON file). Since the leader often successfully defends multiple times in a row, fetching their generations every time is unnecessary.
**Action:** Lift the `leader_gens` fetch out of the loop. If the challenger wins, simply update the cached `leader_gens` to the `challenger_gens`. This reduces the number of API calls during the duel phase from `2N` to `N+1` (where N is the number of challengers), saving significant time and reducing GitHub API rate limit consumption.
